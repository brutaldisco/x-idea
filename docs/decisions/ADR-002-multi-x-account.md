# ADR-002: X 連携を複数アカウント（最大 3）にする

- 日付: 2026-09-05
- 状態: 採用
- 関連: 設計書 14.2 / 18.1 / 19 章 / T-101b

## 文脈

v3.1 までは `x_account` をシングルトン（0..1 行）としていた。ユーザー要望により、**同じ人の別 X アカウント** を最大 3 つまで連携できるようにする。

## 決定

- `x_account` は複数行。`x_user_id` を一意キーにし、同一アカウントの再連携は上書き更新する。
- 上限は 3。4 つ目の追加は拒否する。
- `sources.x_account_id` と `sync_runs.x_account_id` を追加し、どのアカウント由来かを保持する。
- 同期カーソル（`last_sync_head_tweet_id` / `last_synced_at`）は `settings` から `x_account` へ移し、アカウント別に持つ。
- アプリ側のログイン・ユーザー切替・`user_id` は追加しない。あくまで「自分の複数アカウント」。

## 影響

- `sync_bookmarks` はアカウント単位で直列に回す（アカウントごとに `dedupe_key`）。
- 削除したアカウントの Source は残す（`x_account_id` は NULL になる）。
- コストはアカウント数に比例する。スペンディングリミットは X 側で必須のまま。
- 追加時は X の現在セッションを使うと既存アカウントの再同意になる。`/settings/x/add` でユーザー名/メールを受け取り、`force_login=true` + `screen_name` とログアウト経由で別アカウントのログイン画面を開く。パスワードはアプリに入力させない。
