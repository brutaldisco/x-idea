# ADR-029: 動画ダウンロードの一時停止は書き込み済みバイトから再開する

- 日付: 2026-10-15
- 状態: 採用
- 関連: ADR-007、ADR-021、ADR-023、ADR-025、ADR-026、ADR-028、設計書 8 章（SC-15）/ 14.6

## 文脈

実行中の「停止」は対象をすべて `queued` に戻し、画面上の進捗も消していた。
遅い 1 本だけを止めたいときに全体が止まり、再開時は受信量 0 から描き直すため、
最初から取り直したように見えた。未書き込みの並列チャンクと、
`close` 前の IndexedDB 上書きが、カーソルを小さくすることもあった。

## 決定

1. **状態 `paused`**  
   書き込み済みバイトがあるダウンロードを一時停止すると `paused` にする。
   1 バイトも書いていなければ `queued` のまま。`paused` はキュー一覧に残し、
   途中ファイル掃除の対象にしない。自動再開（リース切れの `downloading` や
   進捗あり `failed`）には含めない。

2. **ボタン**  
   実行中の全体「一時停止」と、ダウンロード中の各行「一時停止」。
   再開は「途中から再開」「すべて開始」「この動画だけ」。
   他のダウンロードが走っていても、止めた 1 本だけを続きから開始できる。

3. **カーソル**  
   正本は `close` 後の本体 + `.part`。ディスクが読めたらそのサイズを
   `progress_bytes` と IndexedDB に書く。ディスクが 0 のときは、
   既存の IndexedDB / `progress_bytes` を 0 で消さない。
   通常の保存は進んだ位置だけを採用する。再開時の表示もその位置から始め、
   0% に戻さない。`start` は `paused` を `downloading` にできる。

## 影響

- 遅い動画だけを止めても、並走中の他の動画は続く。
- 再開は保存済みバイトの Range から取る。取消だけが途中ファイルを捨てる。
- マイグレーションは不要（`status` は TEXT）。
