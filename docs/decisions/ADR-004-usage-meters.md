# ADR-004: Settings で残量を先に見せ、なくなったら追加する

- 日付: 2026-09-05
- 状態: 採用
- 関連: ADR-003、設計書 8.7 / 16.3 / 35 章 T-210

## 文脈

X API はクレジット前払い（Owned Reads $0.001/リソース）。ユーザーは「なくなったら追加する」運用を望み、Settings で残量とアカウント別の使用が見たいと指示した。Gemini も日次枠が小さい。X の公式残量 API（`GET /2/usage/credits`）は App Bearer が必要で、アカウント別内訳は返さない。

## 決定

- Settings 最上部に使用量メーターを置く。主表示は **残量**（使用量ではない）。
- X 残量の優先順：① `GET /2/usage/credits`（`X_BEARER_TOKEN`、15 分キャッシュ）② コンソール残量のスナップショット − 以降の推定使用 ③ 追加記録合計 − 生涯推定使用。
- 推定使用は `sync_runs.est_cost_usd` と、取り込み済み `sources`（origin=`x_bookmark`）× $0.001 の大きい方。アカウント別も同じ。
- 追加・残量合わせは `x_credit_ledger`。`user_id` は追加しない。
- `x_api_enabled` は人間が ON にする。メーター実装ではトグルを勝手に ON にしない。

## 影響

- Settings に日次バーとアカウント別バーが並ぶ。
- 公式残量が取れないときは見積もりである旨を出す。
