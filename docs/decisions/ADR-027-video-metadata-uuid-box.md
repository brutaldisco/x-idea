# ADR-027: 動画のサムネ位置は容器末尾の uuid ボックス

- 日付: 2026-09-22
- 状態: 採用
- 関連: ADR-007、ADR-026、設計書 8 章（SC-15）

## 文脈

サムネイルの秒数を `{動画}.mp4.lvl.json` として動画と同じフォルダに置いていた。Finder の一覧に JSON が混ざる。対応はファイル名なので、動画のリネーム、別フォルダへの移動、1 本だけのコピー、親フォルダやライブラリのルートの改名で切れる。

## 決定

MP4 / MOV / M4V（ISO BMFF）では、メタデータを動画ファイル自身の末尾に置く。

1. トップレベルボックスはヘッダーだけ走査する。映像・音声のバイトは読まない。
2. サイズ 0 のボックス、またはボックスサイズの合計がファイルサイズと一致しない容器には書かない。
3. 一致するときだけ、末尾に固定長 280 バイトの `uuid` ボックスを追加する。
4. 同じ動画への再保存は、そのボックスだけを同じ長さで上書きする。ファイルサイズは増えない。
5. 書き込み後にその範囲を読み戻し、バイトが一致しなければ追加分を元のサイズに戻す。上書きに失敗したときは直前のボックスを書き戻す。
6. 既存の `.lvl.json` は、容器への書き込みと読み戻しが成功したあとで削除する。
7. 対応していない形式だけ、従来のサイドカーを残す。
8. ボックスの中にファイル名・相対パス・フォルダ名は入れない。動画を消すとメタデータも一緒に消える。

ユーザー型 UUID は `3f6a0c1e-8b24-4d7a-9f50-6c1e8a4b2d90`。ペイロード 256 バイトの先頭は version `1`、フラグ（bit0 = サムネ秒あり）、6 バイトの予約、ビッグエンディアン float64 の秒、残りは 0。

## 影響

- リネーム、移動、1 本だけのコピー、親フォルダやライブラリ名の変更後も秒数は残る。
- アプリからの保存は File System Access の `createWritable({ keepExistingData: true })` でボックスの位置だけを書く。この API は既存ファイル全体を一時コピーすることがある（ADR-026）。移行スクリプトは末尾への部分書き込みで、映像バイトを書き換えない。
