# ADR-025: 動画ダウンロードのハートビート・リースと中断の自動再開

- 日付: 2026-09-15
- 状態: 採用（2026-09-20 改定: ハートビートは進捗時のみ + 応答なし検出）
- 関連: ADR-007、ADR-021、ADR-023、設計書 8 章（SC-15）/ 14.6

## 文脈

ADR-023 までの仕組みで「停止しても失われない」は達成できたが、直近の
ダウンロード停止（全件が `queued` に戻った正常停止）を調査したところ、
運用上 3 つの構造的な穴が残っていた:

1. **停止の記録が残らない**。停止後の DB は `queued` が並ぶだけで、
   いつ・どこまで進んで・なぜ止まったかを後から調べる手がかりがない。
2. **中断したまま自動復帰しない**。タブを閉じる・スリープ・クラッシュで
   `downloading` のまま取り残された項目は、ユーザーが気づいて
   「すべて開始」を押すまで何時間でも止まったままになる。
3. **複数タブで同一動画を同時ダウンロードできてしまう**。取り残された
   `downloading` 項目はどのタブからでも再開でき、2 つのタブが同じ
   ファイルへ同時に書き込むと破損しうる。

## 決定

`video_downloads` に `last_progress_at` / `progress_bytes` /
`progress_total` を追加し（migration 0017）、ダウンロード中の
**ハートビート**をリースとして使う。

1. **ハートビート**: ダウンロード中のクライアントは 8 秒間隔
   （`VIDEO_HEARTBEAT_MS`）で `POST /api/videos/queue/[id]`
   `{action: "progress", received, total}` を送り、サーバーは
   `last_progress_at` と停止位置を更新する。進捗コールバック
   （バックグラウンドタブでも動く）とタイマーの両方から送る。
2. **リース**: `start` は `queued` / `failed` に加えて、
   `last_progress_at` が 90 秒（`VIDEO_LEASE_STALE_MS`）以上古い
   `downloading` だけを `downloading` に更新できる。リースが生きている
   `downloading` を開始しようとすると **409「別のタブで実行中です」**。
   90 秒は、バックグラウンドタブのタイマー絞り込み（約 1 分に 1 回）を
   吸収できる長さ。
3. **自動再開**: Videos タブを開いたとき、リース切れの `downloading`
   （= 前のセッションの取り残し）があれば、フォルダの書き込み許可が
   済んでいる場合に限り自動で再開する。許可プロンプトは出さない。
   `queued`（手動停止を含む）と `failed`（原因を見てから再開したい）
   は自動では動かさない。
4. **表示**: リースが生きている `downloading` は「別のタブで実行中です」、
   リース切れは「中断しています（再開できます）」。停止位置は
   「1.2 GB まで保存済み」のように表示する。

## 影響

- 停止・中断の調査が「`last_progress_at` / `progress_bytes` を見る」で
  済むようになる（いつ生きていたか・どこまで進んだかが残る）。
- タブを閉じる・スリープ・クラッシュで中断しても、次に Videos タブを
  開いたとき自動で途中から再開する。
- 2 つのタブが同じ動画を同時にダウンロードしてファイルを破損する
  リスクがなくなる（サーバー側のリースで排他）。
- ハートビートは実行中の 1 本あたり 8 秒に 1 回の小さな POST
  （同時最大 2 本）で、負荷は無視できる。

## 改定（2026-09-20: スタール対策）

大きなファイルが途中で 0 B/s のまま動かなくなり、しかも再開できない
報告を受けて調査したところ、ハートビートが無条件に送られるため
**固まったダウンロードがリースを持ち続け**、他のセッションからは
「別のタブで実行中です」に見えて再開できない構造が分かった。
以下を改定する。

1. **ハートビートは受信バイトが増えたときだけ送る**
   （`shouldSendVideoHeartbeat`。初回のリース確立は除く）。
   固まったダウンロードのリースは 90 秒で切れ、中断として再開できる。
2. **応答なし検出**: バイトが 30 秒増えなければ UI に
   「応答なし。再接続しています…」を出す。75 秒（リース切れより前）で
   その本だけ切断し、保存済み位置から自動で取り直す（最大 3 回。
   尽きたら `failed` にして「ダウンロードが止まりました（応答なし）」
   を残す）。取り直した試行は、ファイル準備（`createWritable` の
   全コピー）が長引くことがあるため、最初のバイトが来るまで
   ウォッチドッグを動かさない。
3. あわせて ADR-021 側で、File System Access の書き込み系呼び出しの
   タイムアウト・並列取得の背圧・スタール尽きのエラー変換を入れ、
   固まったまま無期限に残る経路自体を潰している。
