# ADR-007: 動画は手動ダウンロードのみ、画像は DB（Turso）に保存する

- 日付: 2026-09-05
- 状態: 採用（ADR-005 の動画・保存先に関する部分を改定）
- 関連: ADR-005、ADR-006、設計書 8 章（SC-15）/ 14.6 / 19 章、`docs/design/2026-09-05-video-library.md`

## 文脈

- ADR-005 は「画像・動画はローカルディスクに保存し、Vercel では `pnpm dev` 保存役（コンパニオン）経由で書く」とした。しかし **普段使いでローカルサーバーを常駐させない** 方針がユーザーにより確定した（他プロジェクトの開発サーバーとポート競合するため）。
- 容量破綻の主因は動画であり、画像は WebP 化すれば DB に入るサイズである。
- 本番 URL からローカル PC への直接書き込みはブラウザの制約上できないが、**File System Access API**（`showDirectoryPicker`）ならローカルサーバーなしで「OS に見えるフォルダへの書き込み」ができる（Chrome/Edge のみ）。

## 決定

1. **画像と動画サムネイルは WebP に変換して DB（Turso）の `media_blobs` に保存**する。本番・ローカルで同一の挙動とし、コンパニオン／`MEDIA_ROOT` への保存は開発用途に限定する（Settings の案内と自動同期は撤去）。
2. **動画本体は自動保存しない**。Reader の動画はサムネイル＋「X で見る」。残したい動画は「あとで保存」でキュー（`video_downloads`、**queued は最大 15 件**）に入れる。
3. ダウンロードは **Videos タブ（SC-15）から手動実行**し、File System Access API でユーザーが選んだルート配下に `{x_account_id}/{フォルダ}/{tweet_id}_{media_key}.mp4` として書く。分類フォルダは 1 階層のみ（作成・移動・削除可）。引っ越しはアカウントフォルダ単位のコピー＋ルート再リンク。
4. 画質は `variants` の **最大 `bit_rate` の mp4**。低速回線対策として **8MB チャンクの Range 取得＋IndexedDB レジューム**（`GET /api/media/[id]/file`、Vercel Hobby の 300 秒上限を考慮）。
5. プレーヤーはブラウザ標準 `<video controls>`（object URL）。Safari/Firefox はフォルダ保存非対応のため通常ダウンロードにフォールバック。

## 影響

- Turso の容量はテキスト＋WebP 画像のみとなり、動画による破綻リスクは消える（目安: 5GB で画像約 2.5 万〜8 万枚）。Settings に DB メディア使用量メーターを置く。
- 動画の保存は「選んだものだけ」になり、削除済み動画の保全はユーザーの選択次第となる。
- 動画ライブラリは Chrome/Edge 限定機能になる（本アプリは ADR-006 によりすでに Chrome 前提）。
- Source 削除で DB 行は消えるが、ダウンロード済みの実ファイルはユーザーのフォルダに残る（サーバーからは触れない）。
